# 12. 受入基準・KPI・用語集

## 12.1 受入基準（Acceptance Criteria）

### AC-1: 手法カタログ（BR-001）
- 構造化されたカタログに 20 手法以上が登録され、各エントリに出典種別・条件・必要データ・レジーム・実装容易度が入っている。
- 実装済み戦略モジュールとカタログIDが 1:N でトレースできる。

### AC-2: 複合意思決定（BR-002）

> **改訂**: 「発注」までの自動化は A案では対象外。判定は「発注指示カードの生成」までとする。
- 3 戦略以上が同時に稼働し、レジーム判定に応じてウェイトが変化することを、ログとUIで確認できる。
- 同一銘柄への相反シグナル発生時に、DEC-023 のルール通りに解決されることをテストで確認できる。
- 全発注に対し、寄与戦略と条件スナップショットが 100% 記録されている。
- 却下シグナルが理由コード付きで記録されている。

### AC-3: リアルタイム損益（BR-003）
- 価格更新から画面反映までの遅延が、計測 1,000 サンプルの p95 で 1 秒以内。
- 当日純損益が、証券会社の当日実現損益＋評価損益と、既定の許容差以内で一致する（手数料・金利の期ずれを除く）。
- 戦略別・銘柄別・期間別の集計が正しいことを、既知データで検証できる。
- 通信断時に「切断中」と最終更新時刻が表示される。

### AC-4: リスク調整後リターンの改善（BR-004）
- OOS 期間において、アンサンブルの最大DDが、最良単一戦略比で 20% 以上小さい。
- 同期間のシャープレシオがアンサンブル ≥ 最良単一戦略 × 0.9 を満たす（リターンを大きく犠牲にしていない）。

### AC-5: 検証の健全性（BR-005）
- ルックアヘッド検査（未来データ参照の自動検出）に合格。
- ウォークフォワード結果が公開され、パラメータ感度がプラトーであることを示せる。
- ペーパートレード実績とバックテスト期待値の乖離が ±30% 以内。

### AC-6: 破滅的損失の防止（BR-006）
- 以下の発動テストが全て成功する。
  1. 日次損失上限到達 → 新規建て停止
  2. ポートフォリオ・ヒート上限到達 → 新規シグナル却下
  3. 損切り未設置検知 → 該当ポジションの強制クローズ
  4. データ接続断 → 新規建て停止
  5. 発注API障害 → 停止と通知、復旧後の再同期
  6. キルスイッチ → 全戦略停止＋全建玉クローズ
  7. 発注レート超過 → 抑止
- 上記テストが自動化され、リグレッションとして繰り返し実行できる。

### AC-7: 説明可能性・監査（BR-007）
- 任意の約定を選択すると、判断根拠が 1 クリックで表示される。
- 監査ログから、任意の意思決定を時系列で再構成できる。

### AC-8: 運用容易性（BR-008）
- 設定ファイル／UI から、戦略の有効化・無効化・パラメータ変更が、コード変更なしに行える。
- 変更履歴が残り、いつ何を変えたかを追跡できる。

### AC-9: 半自動運用（D-06）
- 通知受信から「発注済み」記録までが **3タップ以内**で完了する。
- 締切60分前の通知と、未発注時の最終リマインドが、設定どおりの時刻に送信される。
- 見送り／期限切れシグナルが自動的に記録され、仮想成績が追跡される。
- 取引履歴CSVを取り込むと、暫定計上された約定価格が実約定価格へ自動補正され、差分が記録される。
- 同じCSVを2回取り込んでも結果が変わらない（冪等）。

### AC-10: マルチデバイス対応（D-07）
- 320px〜デスクトップ幅まで、横スクロールが発生しない。
- iOS Safari / Android Chrome / デスクトップ Chrome で、主要動線（通知確認→発注済み記録→損益確認）が完了する。
- PWAとしてホーム画面に追加でき、オフラインで直近のシグナル・建玉・損益を閲覧できる。
- スマートフォンで「◎ 主」とされた機能（`docs/15` §15.4）がすべて当該デバイスで完結する。
- タップ領域が最小 44×44 px を満たす。

## 12.2 KPI（運用開始後に継続監視する指標）

| 分類 | KPI | 目標（初期案） |
|---|---|---|
| 収益 | 月次純損益 | プラス月の比率 60% 以上 |
| 収益 | プロフィットファクタ（実運用） | ≥ 1.2 |
| 収益 | 平均R（1トレードあたり） | > 0.1R |
| リスク | 最大ドローダウン | ≤ 15%（超過時は自動デレバレッジ） |
| リスク | 日次損失上限の抵触回数 | 月 1 回以下 |
| リスク | リスク上限違反（システム的逸脱） | 0 件 |
| 品質 | 誤発注・二重発注 | 0 件 |
| 品質 | 突合差異（件数・金額） | 0 件 |
| 品質 | 実現スリッページ / 想定スリッページ | ≤ 2.0 |
| 品質 | 損切り注文の設置成功率 | 100% |
| 運用 | 立会時間中の稼働率 | ≥ 99.9% |
| 運用 | シグナル→発注のレイテンシ p95 | ≤ 100ms |
| 運用 | 損益表示レイテンシ p95 | ≤ 1s |
| 戦略 | 稼働戦略数／うち基準を満たす戦略数 | 稼働 5 以上、基準充足率 80% 以上 |

| **半自動** | **シグナル実行率** | **≥ 90%** |
| **半自動** | **損切りシグナルの実行率** | **100%** |
| **半自動** | 執行遅延（シグナル生成→発注済み記録の中央値） | ≤ 30分 |
| **半自動** | 機会損失（見送りシグナルの仮想損益） | 月次で純損益の 20% 以内 |
| **半自動** | 約定価格の補正誤差（暫定 vs 実約定） | 中央値 ≤ 0.5% |
| **半自動** | CSV取込の実施頻度 | 週1回以上 |
| **UI** | スマートフォンでの初回表示（LCP） | ≤ 2.5秒 |
| **UI** | 通知の到達率 | ≥ 99% |

## 12.3 用語集

| 用語 | 定義 |
|---|---|
| シグナル | 戦略モジュールが出力する売買候補。方向・確信度・エントリー・損切り・利確条件を含む |
| レジーム | 相場環境の分類（トレンド／レンジ、高ボラ／低ボラ、上昇／下降） |
| アンサンブル | 複数戦略のシグナルを重み付けして統合し、単一の意思決定に集約する仕組み |
| 確信度（conviction） | 戦略が自らのシグナルに与える 0〜1 の強さ |
| ポートフォリオ・ヒート | 同時保有ポジションの想定リスク（損切りまでの損失）の合計 |
| R倍数 | 1トレードの損益を、そのトレードの初期リスク額で割った値 |
| プロフィットファクタ（PF） | 総利益 ÷ 総損失 |
| 最大ドローダウン（最大DD） | 資金曲線の最高値からの最大下落率 |
| スリッページ | 想定価格と実際の約定価格の差 |
| ルックアヘッド | 検証時にその時点で入手できない未来情報を使ってしまうこと |
| 生存者バイアス | 上場廃止銘柄等を除いたデータで検証し、成績が過大評価されること |
| ウォークフォワード | 学習期間と検証期間をずらしながら繰り返し検証する手法 |
| OOS（Out-of-Sample） | パラメータ最適化に使っていない期間のデータ |
| メタラベリング | 一次シグナルを取るか否かを、二次モデルが判定する二段階構成 |
| VCP | ボラティリティ収縮パターン。押し幅と出来高が段階的に縮小する形状 |
| ピラミッディング | 含み益の進展に応じた買い増し |
| ドテン | 保有ポジションを決済し、同時に反対方向のポジションを建てること |
| キルスイッチ | 全戦略の停止と全建玉のクローズを一括で行う緊急停止機能 |
| リコンサイル（突合） | 自システムの建玉・損益と、証券会社側の記録を照合すること |
| フェイルクローズ | 異常時に「何もしない（発注しない）」を既定動作とする設計方針 |
| 冪等キー | 同じ発注要求を複数回送っても 1 回しか実行されないことを保証する識別子 |
| point-in-time | 「その時点で観測できた値」を保持し、後日訂正値の混入を防ぐデータ管理方式 |
| 半自動（A案） | 判断・リスク管理・記録を自動化し、発注操作のみ利用者が証券会社アプリで行う運用形態 |
| 発注指示カード | 利用者に提示する1件分の売買指示。銘柄・数量・執行枠・期限・根拠・損切り価格を含む |
| 実行率 | 発注指示に対して実際に発注された割合。半自動運用における最重要KPI |
| 機会損失 | 見送り／期限切れとなったシグナルを実行していた場合の仮想損益 |
| 暫定計上 | CSV取込前、参考価格で仮に計上した損益。確定値と区別して表示する |
| 執行枠 | S株の3つの執行タイミング（9:00 / 12:30 / 15:30）のいずれか |
| PWA | Progressive Web App。ホーム画面に追加でき、プッシュ通知やオフライン閲覧に対応するWebアプリ |
