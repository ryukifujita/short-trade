# 02. ステークホルダと利用シナリオ

## 2.1 ステークホルダ

| 区分 | 役割 | 本ツールへの関心事 |
|---|---|---|
| オーナートレーダー（主利用者） | 自己資金で短期売買を行う個人／小規模チーム | 収益、ドローダウン、稼働の安定性、説明可能性 |
| 戦略開発者 | 手法の調査・ルール化・バックテスト | 検証環境、再現性、パラメータ管理 |
| システム運用者 | 稼働監視・障害対応（初期はオーナー兼任） | 監視、アラート、フェイルセーフ |
| リスク管理者 | 上限設定・逸脱検知（初期はオーナー兼任） | 上限遵守、キルスイッチ、監査ログ |
| 証券会社（外部） | 発注API・約定・残高提供 | API規約、レートリミット、自動売買の可否 |
| 市場データベンダ（外部） | 板・歩み値・時系列・ファンダ・ニュース | 遅延、配信品質、再配信条件、コスト |
| 税理士／税務当局（外部） | 損益の申告 | 年間損益の正確性、取引明細の保全 |

## 2.2 利用者像（ペルソナ）

- **P1: 兼業スイングトレーダー**
  日中は本業。場中に画面を見られない。前日夜または寄り前にシグナルを確認し、自動執行に任せたい。
  重視: 自動化率、通知、夜間のレポート。
- **P2: 専業デイトレーダー**
  場中フルタイム。自動売買と裁量を併用。自動側の損益・建玉を秒単位で把握し、必要なら介入したい。
  重視: リアルタイム性、手動オーバーライド、キルスイッチ。
- **P3: 戦略開発者（兼業／専業いずれも）**
  新しい手法を実装し、バックテスト→ペーパートレード→少額実弾へ昇格させたい。
  重視: 検証の厳密さ、戦略間の比較、パラメータ履歴。

## 2.3 運用の1日（トレーディングデイのタイムライン・JST）

| 時刻 | フェーズ | システムの振る舞い |
|---|---|---|
| 〜07:00 | 夜間バッチ | 前日終値・コーポレートアクション・決算・材料ニュースの取込、ユニバース再構築、指標再計算 |
| 07:00-08:00 | 事前計算 | レジーム判定、戦略ウェイト算出、監視候補リスト（ウォッチリスト）生成、リスク枠の当日割当 |
| 08:00-09:00 | 寄り前 | 気配・板寄せ気配の監視、ギャップ検知、寄付シグナル（決算ギャップ等）の生成 |
| 09:00-11:30 | 前場 | ティック処理、シグナル生成、合議、発注、建玉・損益のリアルタイム更新 |
| 11:30-12:30 | 昼休み | 前場サマリ生成、リスク枠の再評価、必要ならウェイト調整 |
| 12:30-15:25 | 後場 | 同上。引け前は手仕舞い方針（デイ戦略の強制クローズ）を適用 |
| 15:25-15:30 | クロージングオークション | 引け成行・引け指値の執行、当日デイポジションの完全クローズ確認 |
| 15:30-18:00 | 場後 | 約定突合（リコンサイル）、日次損益確定、戦略別成績更新、日報生成・通知 |
| 18:00〜 | 学習・検証 | 当日データ追記、ウォークフォワード再学習（週次／月次）、パラメータドリフト検知 |

> 注: 東証の立会時間は前場 9:00-11:30、後場 12:30-15:30（クロージングオークション 15:25-15:30）を前提とする。
> 立会外・PTS・米国市場対応は Phase 5 のオプション。

## 2.4 主要ユースケース

### UC-01 シグナル生成から自動発注まで
1. 市場データ受信 → 各戦略モジュールがシグナル候補を出力
2. 意思決定エンジンがレジーム・重み・相関・既存建玉を考慮して統合
3. リスクゲートが上限・流動性・銘柄制限を検査
4. 執行エンジンが注文種別（成行／指値／IOC／引け）を選択し発注
5. 約定通知を受け、建玉・損益・戦略別成績を更新
6. 判断根拠（寄与戦略・条件スナップショット）を監査ログへ保存

**例外**: リスクゲート却下、発注API障害、値幅制限（S高／S安）、板不足 → `docs/07_リスク管理要求.md`

### UC-02 リアルタイム損益の確認
- ダッシュボードに、口座全体／戦略別／銘柄別の実現損益・含み損益・手数料等控除後の純損益を表示。
- 「今日」「今週」「今月」「累計」を切替。R倍数・勝率・PF を同時表示。

### UC-03 手動介入（オーバーライド）
- 個別ポジションの即時クローズ、特定戦略の一時停止、全戦略の停止＋全建玉クローズ（キルスイッチ）。
- 介入操作は理由コード付きで監査ログに残る。

### UC-04 新戦略の追加と昇格
- 戦略モジュールを実装 → バックテスト合格 → ペーパートレードで一定期間・一定成績 → 少額実弾 → 本番ウェイト割当。
- 各ゲートの合格基準は `docs/08_検証要求.md` に定義。

### UC-05 不調戦略の自動デレバレッジ
- 直近成績が閾値を割った戦略のウェイトを自動逓減、閾値を大きく割れば自動停止し通知。

### UC-06 障害・切断時の安全停止
- データ／発注APIの切断を検知したら、新規建てを停止。既存建玉は事前に置いた逆指値（ブローカー側OCO）で保護。
- 復旧時は建玉・注文の状態をブローカー側の情報を正として再同期してから再開。

### UC-07 日次・月次レポート
- 日次: 損益、約定一覧、戦略別寄与、リスク上限の使用率、逸脱の有無。
- 月次: 資金曲線、最大DD、シャープ／ソルティノ、戦略相関、期待値のドリフト。
