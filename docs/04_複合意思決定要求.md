# 04. 戦略モジュール化と複合意思決定（アンサンブル）要求

本章は BR-002 / BR-004 / BR-007 に対応する。「複数の名手の判断を合議制で束ねる」中核部分の要求を定義する。

## 4.1 全体パイプライン

```
市場データ ─┬─> [特徴量エンジン] ─> [戦略モジュール群] ─> シグナル候補
            │                          (ST-01 … ST-27)
            └─> [レジーム判定器] ─────────┐
                                          v
                              [アンサンブル意思決定エンジン]
                          （重み付け合議 → 競合解決 → 確信度算出）
                                          v
                                  [資金配分・サイズ決定]
                                          v
                                    [リスクゲート]  ── 却下 ─> 監査ログ
                                          v
                                    [執行エンジン] ─> 発注 ─> 約定
                                          v
                            [ポジション／損益／成績の更新]
```

## 4.2 戦略モジュールの統一インタフェース

| ID | 要求 | 優先度 |
|---|---|---|
| DEC-001 | 全戦略は共通インタフェースを実装し、意思決定エンジンから戦略の内部実装に依存せず扱えること | Must |
| DEC-002 | 戦略は状態を持たず（または明示的に外部保存し）、同一入力に対し同一出力を返す決定性を持つこと | Must |
| DEC-003 | 戦略は「自分が有効と考えるレジーム」を宣言できること | Must |
| DEC-004 | 戦略は自身のシグナルに対し必ずエントリー価格・**損切り価格**・利確／手仕舞い条件を付与すること（損切り未設定のシグナルは無効） | Must |

### シグナルのデータ要求（論理項目）

| 項目 | 説明 |
|---|---|
| `strategy_id` | 発生元の戦略（カタログID と紐づく） |
| `symbol` / `side` | 銘柄・売買方向（買い／空売り） |
| `conviction` | 確信度 0.0〜1.0（戦略内での相対的な強さ） |
| `horizon` | 想定保有期間（スキャル／デイ／スイング） |
| `entry_type` / `entry_price` | 成行・指値・逆指値・引け等 と価格 |
| `stop_price` | **必須**。初期損切り価格 |
| `target_price` / `exit_rule` | 利確目標、またはトレーリング等の手仕舞いルール |
| `expected_r` | 想定リスクリワード（(target-entry)/(entry-stop)） |
| `regime_fit` | 現在レジームへの適合度 0.0〜1.0 |
| `rationale` | 成立条件のスナップショット（説明可能性用） |
| `valid_until` | シグナルの有効期限 |

## 4.3 レジーム（相場環境）判定

| ID | 要求 | 優先度 |
|---|---|---|
| DEC-010 | 市場全体のレジームを、少なくとも「トレンド／レンジ」×「高ボラ／低ボラ」の4象限＋方向（上昇／下降）で判定すること | Must |
| DEC-011 | レジーム判定に用いる指標を設定で差し替え可能とすること | Should |
| DEC-012 | レジームの切替は頻繁なフラつきを避けるため、ヒステリシス（確定条件・最短維持期間）を持つこと | Must |
| DEC-013 | 個別銘柄レベルのミクロレジーム（当該銘柄のトレンド有無・ボラ水準）も判定できること | Should |

**判定指標の候補**: 指数（TOPIX／日経平均）の 200MA・50MA の傾きと位置関係、ADX、実現ボラティリティ、
日経VI、騰落レシオ、新高値-新安値銘柄数、値上がり銘柄比率、業種間の分散度、金利・為替の変化率。

## 4.4 アンサンブル（合議）方式

| ID | 要求 | 優先度 |
|---|---|---|
| DEC-020 | 複数戦略のシグナルを、戦略ウェイト × 確信度 × レジーム適合度 で統合スコア化すること | Must |
| DEC-021 | 統合スコアが閾値を超えたものだけを発注候補とすること（閾値は設定可能） | Must |
| DEC-022 | 戦略ウェイトは (a) 静的設定 (b) レジーム別設定 (c) 直近成績による動的調整 の3方式を選択・併用できること | Must |
| DEC-023 | 同一銘柄で相反するシグナル（買いと空売り）が出た場合の競合解決ルールを定義・適用すること | Must |
| DEC-024 | 既存建玉と同方向の新規シグナルは「買い増し（ピラミッディング）」として扱い、初期リスク総量を超えないこと | Must |
| DEC-025 | 既存建玉と逆方向のシグナルは、原則「手仕舞い」として解釈し、ドテンは明示設定時のみ許可すること | Must |
| DEC-026 | 戦略間の相関（同時に同じ銘柄・同じ方向に出る度合い）を計測し、実効的な集中を抑制すること | Should |
| DEC-027 | メタ判定（「このシグナルを実際に取るか否か」を過去実績から学習する二段階判定）を任意で有効化できること | Could |
| DEC-028 | 合議の結果と各戦略の寄与度を、人間が読める形で必ず記録・表示すること | Must |

### 競合解決ルール（DEC-023 の既定）
1. 統合スコアの高い側を採用する。
2. スコア差が閾値未満なら**両方見送り**（不確実な局面では取引しない）。
3. 時間軸が異なる場合は、長い時間軸（スイング）の方向をトレンドとして優先し、短い時間軸のシグナルはその方向のみ採用（既定はON、設定で解除可）。

### 動的ウェイト（DEC-022c）の既定式
- 各戦略の直近 N トレード（または N 日）の **リスク調整後成績**（例: 平均R、シャープ）を評価。
- 評価をランク化し、ウェイト = 基準ウェイト × 調整係数（下限 0、上限 2倍）。
- 過剰反応を防ぐため、評価は最低試行回数を満たすまで基準ウェイトを維持する。
- 成績が下限閾値を割った戦略は自動停止し、通知する（UC-05）。

## 4.5 資金配分・ポジションサイズ

| ID | 要求 | 優先度 |
|---|---|---|
| DEC-030 | 1トレードのリスク額は「(エントリー価格 − 損切り価格) × 数量」で定義し、口座資産に対する比率上限を設けること | Must |
| DEC-031 | ポジションサイズ手法として MM-01（固定リスク比率）を既定とし、MM-02（ATR）・MM-03（分数ケリー）を選択可能とすること | Must |
| DEC-032 | 確信度・レジーム適合度に応じてサイズを可変にできること（上限は必ず DEC-030 の枠内） | Should |
| DEC-033 | 同時保有ポジション全体の想定リスク合計に上限を設けること（ポートフォリオ・ヒート） | Must |
| DEC-034 | 銘柄の流動性（直近平均出来高・売買代金）に対する自己の注文比率に上限を設けること | Must |
| DEC-035 | 資金曲線が自身の移動平均を下回った場合に、全体サイズを自動縮小できること（MM-06） | Should |
| DEC-036 | 単元株制度・呼値・信用建余力・現物買付余力の制約を満たす数量に丸めること | Must |

## 4.6 説明可能性（Explainability）

| ID | 要求 | 優先度 |
|---|---|---|
| DEC-040 | すべての発注に対し「どの戦略が、どの条件で、どれだけ寄与したか」を保存すること | Must |
| DEC-041 | UI 上で1クリックで、当該トレードの判断根拠（条件値、レジーム、ウェイト、競合の有無）を参照できること | Must |
| DEC-042 | 機械学習を用いる場合も、特徴量寄与（例: SHAP 等）を提示できること | Should |
| DEC-043 | 発注しなかったシグナル（却下シグナル）も理由コード付きで記録すること | Must |

## 4.7 学習・再学習

| ID | 要求 | 優先度 |
|---|---|---|
| DEC-050 | パラメータ・モデルの再学習はウォークフォワード方式で行い、未来情報を使わないこと | Must |
| DEC-051 | 再学習の頻度（週次／月次／四半期）と、切替時の並行運用期間を設定できること | Should |
| DEC-052 | モデル／パラメータはバージョン管理され、どの期間にどのバージョンが稼働したか追跡できること | Must |
| DEC-053 | 入力データ分布のドリフトを検知し、閾値超過時は通知して自動運用を保守モードへ落とせること | Should |
