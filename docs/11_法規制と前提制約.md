# 11. 法規制・コンプライアンス要求と前提・制約（CR）

> 本章は要求定義のための一般的な整理であり、法的助言ではない。
> 実運用の前に、必ず**証券会社の約款・API利用規約の確認**と、必要に応じて**専門家（弁護士・税理士）への相談**を行うこと。

## 11.1 適用範囲の前提

| ID | 前提 | 内容 |
|---|---|---|
| CR-001 | 自己資金による自己売買 | 本ツールは、利用者本人の資金・本人名義口座での売買のみを対象とする |
| CR-002 | 第三者への助言・運用受託を行わない | 対価を得てシグナルを提供する、他人の資産を運用する等の行為は本スコープ外。行う場合は金融商品取引法上の登録（投資助言・代理業／投資運用業）等の要否を別途検討する必要がある |
| CR-003 | ツールの再配布・販売は行わない | 販売・提供を行う場合、上記の登録要否や表示義務の検討が必要となる |
| CR-004 | 収益の保証をしない | 画面・ドキュメント・通知のいずれにおいても、将来の収益を保証・断定する表現を用いない |

| ID | 要求 | 優先度 |
|---|---|---|
| CR-010 | 起動時および UI 上に、「自己責任での利用」「収益非保証」の旨を表示すること | Must |
| CR-011 | 第三者にシグナル・損益を共有する機能を実装する場合は、CR-002 の検討結果を踏まえて可否を判断すること | Must |

## 11.2 禁止行為への抵触防止

| ID | 要求 | 優先度 | 対応 |
|---|---|---|---|
| CR-020 | 相場操縦に該当しうる発注パターンを行わないこと | Must | RM-050〜RM-054 |
| CR-021 | 仮装売買・馴合売買に該当しうる自己対当を防止すること | Must | RM-051 |
| CR-022 | 未公表の重要事実に基づく売買（インサイダー取引）を行わないこと | Must | 情報源を公開情報に限定し、データ源のライセンスと公表時刻を記録（DR-021, VR-005） |
| CR-023 | 証券会社の API 利用規約（自動売買の可否、レートリミット、スクレイピング禁止等）を遵守すること | Must | FR-187, RM-053 |
| CR-024 | 市場データの再配信・目的外利用を行わないこと | Must | DR-021 |
| CR-025 | 空売り規制（価格規制、株券手当）に適合すること | Must | RM-044 |

## 11.3 記録・保全

| ID | 要求 | 優先度 |
|---|---|---|
| CR-030 | 全注文・全約定・全判断根拠を、税務・自己検証に足る期間（最低 7 年）保全すること | Must |
| CR-031 | 年間の損益・取引明細を出力できること | Should |
| CR-032 | 特定口座（源泉徴収あり／なし）・一般口座の別を設定でき、税額表示の前提を明示すること | Should |

## 11.4 前提条件（Assumptions）

> 2026-09-10 の確定事項（資金5万円 / 現物のみ / 空売りなし / 完全自動 / SBI証券が第一候補）を反映済み。

| ID | 前提 |
|---|---|
| A-01 | ~~利用する証券会社が、個人向けに発注APIを提供し、自動売買を規約上許容していること~~ → **未成立。SBI証券の国内株式現物について個人向け発注APIを確認できていない**（`docs/13`）。CR-040 / CR-043 の照会が完了するまで、この前提は保留 |
| A-02 | 必要な市場データ（少なくとも現在値・気配・分足・日足・銘柄マスタ）を、要求する遅延で調達できること |
| A-03 | 立会時間中、安定したネットワークと計算資源を確保できること |
| A-04 | 運用資金（初期5万円）は生活資金と分離され、全損しても生活に影響しない範囲であること |
| A-05 | 利用者が短期売買の基礎知識（信用取引、値幅制限、注文種別）を有していること |
| A-06 | 開発・検証に十分な期間（Phase 0〜3 でおよそ 4〜7 か月）を確保できること |

## 11.5 制約条件（Constraints）

| ID | 制約 |
|---|---|
| C-01 | 東証の立会時間・呼値・単元株制度・値幅制限に従う |
| C-07 | **現物取引の差金決済規制**に従う（同一銘柄・同一資金での1日の回転は1回まで）（CR-051） |
| C-08 | **S株（単元未満株）の執行制約**に従う（成行のみ・1日3回の執行タイミング・同一日同一銘柄は各タイミング買/売1件まで）（`docs/14` §14.2） |
| C-09 | **月額固定費 0 円**（有料データ・有料VPSを使わない）（NFR-060） |
| C-02 | 証券会社 API のレートリミット、注文種別、同時発注数の制限に従う |
| C-03 | 市場データのライセンス条件（保存期間、再配信禁止）に従う |
| C-04 | ミリ秒レイテンシ競争は行わない（インフラ上、勝負にならない領域を戦略に選ばない） |
| C-05 | 個人開発規模を想定し、過度に複雑な分散アーキテクチャを採らない |
| C-06 | 予算制約（データ・インフラの月額コスト）を、想定運用資金に対する妥当な比率に収める |

## 11.6 主要リスクと対応方針

| # | リスク | 影響 | 対応 |
|---|---|---|---|
| R-01 | 過剰最適化により実運用で機能しない | 資金毀損 | VR-020〜VR-025、G1〜G5 の昇格ゲート |
| R-02 | バグによる誤発注・暴走 | 大損失 | RM-034（fail-closed）、RM-035（暴走検知）、FR-183（冪等）、少額からの段階移行 |
| R-03 | 証券会社 API の仕様変更・障害 | 停止・機会損失 | アダプタ抽象化（NFR-050）、縮退動作の定義、複数社対応の検討 |
| R-04 | 相場レジームの構造変化 | 期待値低下 | レジーム判定、動的ウェイト、ドリフト検知（DEC-053）、定期再検証 |
| R-05 | 流動性枯渇・ギャップダウン | 損切り価格で約定しない | 流動性制約（RM-016）、ギャップリスクを織り込んだサイズ、イベント跨ぎ制限（RM-042） |
| R-11 | **逆指値が置けない（S株）ことによる損切り遅延** | 想定を超える損失 | RM-001a〜e（論理ストップ、想定損失2倍見積り、1銘柄上限15〜20%、決算跨ぎ禁止） |
| R-12 | **発注APIが確保できず完全自動が実現しない** | 計画の前提崩壊 | CR-040/CR-043 を Phase 0 の最優先タスク化、FR-191（半自動）を Must 化 |
| R-13 | **資金5万円では分散が効かず、実質1銘柄集中になる** | 破産リスク | S株運用を既定化（CR-050）、1銘柄上限（RM-001c） |
| R-14 | **固定費が利益を上回る** | 継続不能 | 月額0円制約（NFR-060〜062） |
| R-06 | 心理的要因での手動介入によるルール破壊 | 期待値の毀損 | 介入の記録と事後レビュー、介入時の理由コード必須化 |
| R-07 | 規約・法令への抵触 | 口座停止等 | CR-020〜CR-025、発注パターンモニタ |
| R-08 | 認証情報の漏洩 | 不正取引 | NFR-020〜NFR-024 |
| R-09 | データ品質不良（欠損・異常値） | 誤シグナル | FR-108、DR-023、遅延データでの発注禁止（NFR-007） |
| R-10 | 開発が長期化し運用に至らない | 機会損失 | 段階スコープ（Phase）、各フェーズで動くものを出す |
