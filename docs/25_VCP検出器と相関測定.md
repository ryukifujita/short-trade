# 25. VCP 検出器・相関測定・ユニバース拡張（夜間作業の記録）

利用者の判断が要らない作業をまとめて進めた。テストは 61 → 75 件。

## 25.1 ST-04 の VCP 検出器（`src/short_trade/detectors.py`）

Phase 2 の4本で唯一動かなかった ST-04 が動くようになった。

### 仕組み

| 手順 | 内容 |
|---|---|
| 1 | ATR(20)×1.5 を閾値とする **因果的ジグザグ**で山・谷を確定する。山は「そこから閾値ぶん下げた日」に初めて見える（`docs/18` の因果性を守る） |
| 2 | 山→直後の谷を1つの「押し」とし、押し幅（%）と区間平均出来高を記録する |
| 3 | 日付 t について、t までに確定し直近90本に山がある押しを新しい順に p3, p2, p1 に割り当てる |
| 4 | `vcp.pivot`＝直近の山、`vcp.p3_low`＝直近の谷。ST-04 の条件式がそのまま参照する |

仕様側は `definitions: vcp: {detector: vcp, lookback: 90, atr_period: 20, atr_mult: 1.5}` と書く。
エンジンは `detector` キーを見て `detectors.py` の登録名を呼ぶ。式で書けないものはすべてこの形にする。

### テストで固定したこと

- 合成した「12% → 7% → 3% の収縮＋出来高縮小 → 出来高2.2倍で上放れ」を検出し、**上放れの翌営業日に建てる**
- **データを打ち切っても打ち切り点より前の検出結果が変わらない**（因果性）
- 山はその当日には見えない（確認日まで待つ）
- 出来高が伴わない上放れでは建てない

### 副産物: 連鎖比較と STREAK

- `vcp.p1 > vcp.p2 > vcp.p3` のような**連鎖比較**を Series で評価できるよう展開器を追加した（Python の連鎖比較は内部で `and` を使うため Series では落ちる）
- `STREAK(cond)`（連続成立日数）を追加し、ST-35 の未定義だった `stage_1_days` を
  `STREAK(close < HIGHEST(high, 150)[-1])[-1]`（レンジ上限の下に居続けた日数＝底固めの長さ）と定義した

## 25.2 相関測定（`correlate` コマンド / `src/short_trade/correlate.py`）

`docs/18` §18.4 の事前予想と実測を並べる。VR-045（0.7 以上は同一因子）の判定に使う。

| 測るもの | 意味 |
|---|---|
| 資金曲線の日次リターンの相関 | 実際に同時に沈むか |
| エントリー（日×銘柄）の重なり（Jaccard） | 同じ日に同じ銘柄を買っているか |

**5万円のサイズ制約下では「1株未満」の却下が支配的でシグナル構造が見えない**ため、
相関は資金 1,000万円・投下額上限なしで測る。目的は成績ではなく構造の把握。

測定器の健全性は「同じ仕様を2本渡すと相関 1.0・Jaccard 1.0 になる」ことで確認した。

## 25.3 ユニバース拡張（`fetch --universe`）

30銘柄の基準線は生存者バイアスが強い（`docs/24` §24.5）。次の一手として、
上場銘柄一覧＋最新日の時価総額（`MktCap` 列）で **プライム市場の時価総額上位 N 銘柄（既定 300）** を取得するコマンドを用意した。
選定結果は `data/jquants/universe.json` に残す。

> これでも「今日の時価総額上位」を選ぶ以上、生存者バイアスは残る。完全な対策（VR-004）は
> 各時点の上場銘柄一覧を月次で保存して当時のユニバースを再現することで、Phase 3 の課題として残す。

## 25.5 2回目の起動ファイルがやること

`run_mac.command` / `run_windows.bat`:
1. 決算発表予定日が無ければ取得（初回のみ）
2. `compare` … リスク率 1% / 2% × スリッページ 0 / 0.1% の比較表 → `data/compare_report.json`
3. `correlate` … Phase 2 の4本の相関 → `data/correlation_report.json`

この2つのファイルを報告してもらえば、リスク率の決定と因子分類の検証が同時に進む。
