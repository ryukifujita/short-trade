# 17. 因子分類と代表手法の選抜（Phase 0 残作業）

`docs/16` §16.6 の「1. カタログ63件に因子タグを付与し、因子ごとに代表手法を1〜2本選ぶ」の実施結果。

**正本は [`catalog/strategies.yaml`](../catalog/strategies.yaml)**（FR-C01）。本章の表はそこから生成している。
手法を追加・変更するときは YAML を編集し、本章を再生成する。

## 17.1 なぜ因子で分類するのか

`docs/16` §16.3 の問題1（見かけの分散）への対処である。

63件を名前で並べると多様に見えるが、**実際には同じことを見ている手法が多い**。
10本の戦略を合議させても、全部が同じ因子なら不調期に10本が同時に沈む。
そこで「何を収益の源泉としているか」で分類し、**因子ごとに代表を選ぶ**。

因子は、次の問いへの答えで決める：**この手法は、誰が・なぜ払ってくれるお金を取りにいっているのか。**

## 17.2 因子の定義（6因子）

| 因子 | 名称 | 収益の源泉として想定していること | 効きやすい局面 |
|---|---|---|---|
| **F1** | トレンド追随・ブレイク | 価格が節目を超えると、乗り遅れた買いと売り方の損切りが続く | 上昇トレンド |
| **F2** | ボラティリティ収縮→拡大 | 値動きが止まった後は大きく動く。方向より「動きの再開」を取る | トレンド／レンジどちらでも |
| **F3** | クロスセクショナル相対強度 | 相対的に強い銘柄は、しばらく相対的に強いままでいやすい | 銘柄間の分散が大きい局面 |
| **F4** | 短期平均回帰 | 短期の売られすぎは、需給の一時的な偏りとして戻りやすい | レンジ・上昇トレンド中の押し |
| **F5** | イベント・ドリフト | 新しい情報が価格に織り込まれるまでに時間がかかる | イベント発生時 |
| **F6** | 需給・オーダーフロー | 板や建玉の偏りが、短期の方向を規定する | 常時（ただし高頻度データが必要） |

**F1 と F4 は符号が逆**（ブレイクを買う／下げを買う）であり、構造的に低相関になりやすい。
ここが分散の主軸になる。F2 は F1 のタイミングを絞る性質があるため、F1 との相関測定を最優先で行う。

### 因子以外の4区分

シグナルを出さないものは因子を持たない。合議の対象外だが、システムには必要である。

| 区分 | 役割 | 例 |
|---|---|---|
| **確認フィルタ** | 単独では優位性が薄く、他戦略の条件を絞るために使う | 酒田五法、ローソク足パターン、ワイコフ |
| **レジーム入力** | 相場環境の判定に使う（DEC-010） | 200日線、一目均衡表、日経VI、金融環境 |
| **資金管理** | サイズと撤退の決定（DEC-030〜036） | 固定比率リスク、ATRベース、R倍数 |
| **原則** | 実装対象ではないが設計方針として反映 | 損切りの規律、規律の外部化、トリプルスクリーン |

| ID | 選んだ理由 |

### F6（需給・オーダーフロー）が空である理由

F6 に属する7件（ST-19 / ST-20 / ST-21 / ST-22 / ST-48 / MK-01 / MK-04）は、
**板・歩み値という有料かつリアルタイムのデータ**か、**ザラ場での執行**を必要とする。
どちらも現在の制約（NFR-061 月額固定費0円 / S株の1日3回執行）に抵触するため、初期スコープでは実装しない。

**結果として、初期の分散はF1・F2・F3・F4・F5の5因子で構成する。**
需給の軸を持てないことは、本構成の弱点として明示的に認識しておく。

## 17.4 Phase 2 で着手する4本

代表8本のうち、Phase 2 では次の4本に絞る。

| # | ID | 手法 | 因子 | 必要データ |
|---|---|---|---|---|
| 1 | ST-06 | タートルズ（ドンチャン20/55） | F1 | 日足のみ |
| 2 | ST-04 | SEPA / VCP | F2 | 日足のみ |
| 3 | ST-09 | クロスセクショナル・モメンタム | F3 | 日足のみ |
| 4 | ST-12 | 短期RSI逆張り（Connors） | F4 | 日足のみ |

**この4本を選んだ理由は「4つの異なる因子を1本ずつ」だからである。**

- 同じ因子から2本取ると、Phase 2 の時点では相関を測る意味がない。
- 4因子を1本ずつ持てば、**Phase 2 の終わりに相関行列を出した時点で、因子分類が正しかったかどうかを検証できる**。
- 4本とも**日足データのみ**で完結し、決算・開示・週足を必要としない。Phase 1 のデータ基盤が最小で済む。

分類が間違っていた場合（例: ST-04 と ST-06 の相関が 0.7 を超えた）、
**F1 と F2 を統合し、空いた枠に別因子を入れる**。この判断を Phase 3 の設計に入る前に行う。

Phase 3 で残りの4本（ST-35 / ST-38 / ST-16 / ST-23）を追加し、8本体制にする。

## 17.5 次の作業 — 条件式の書き下しフォーマット

Phase 1 では、代表8本を次の形式に書き下す。`rules_written: true` になった時点で完了とする。

```yaml
# 例: ST-06 の書き下しフォーマット
id: ST-06
universe:                      # この戦略が見る銘柄
  min_avg_turnover_20d: 50000000   # 円
  exclude: [監理, 整理, 貸借不適格]
regime_filter:                 # 稼働条件（DEC-003）
  index_above_ma200: true
entry:
  condition: "close > max(high[1..20])"
  execution: {slot: "09:00", type: "成行"}
exit:
  stop: "min(low[1..10])"           # 論理ストップ（RM-001a）
  stop_execution: "次の執行枠で成行"
  target: null                      # トレーリングのみ
  trailing: "min(low[1..10])"
  time_stop_days: 40
sizing:
  method: MM-01
  risk_pct: 1.0
  assumed_loss_multiple: 2.0        # RM-001b（ギャップ込み）
constraints:
  max_position_pct: 15              # RM-001c
  no_earnings_hold: true            # RM-001d
params_to_optimize: [20, 10]        # 探索する自由度を明示（VR-025）
```

| ID | 要求（新規） | 優先度 |
|---|---|---|
| FR-C05 | 全戦略は上記フォーマットで記述し、**コードとは別に設定として保持**すること。同じ記述からバックテストと実運用の両方が動くこと（VR-001） | Must |
| FR-C06 | `params_to_optimize` に列挙した以外のパラメータを探索しないこと。**自由度を事前に固定**し、試行回数を記録すること（VR-025 / VR-050） | Must |
| FR-C07 | カタログの `status` が `selected_*` でない手法を、合議に組み込めないこと（システム的に強制） | Must |

## 17.6 検証の順序（Phase 1〜3）

| 順序 | 作業 | 判定 |
|---|---|---|
| 1 | ST-06 を書き下し、単体バックテスト | 既知の挙動を再現するか（基盤の正しさの確認） |
| 2 | ST-04 / ST-09 / ST-12 を書き下し、単体バックテスト | 各 G1・G2 を通過するか |
| 3 | 4本のシグナル系列で**相関行列**を算出 | 全ペアで 0.7 未満か（VR-045）。超えたら因子分類を修正 |
| 4 | 4本の単純等ウェイト合成 vs 最良単一戦略 | 合成が最大DDを下げるか（BR-004 の予備判定） |
| 5 | レジーム別・確信度別の重み付けを導入 | 等ウェイトに勝つか。勝たなければ**単純な等ウェイトを採用する** |
| 6 | Phase 3 で残り4本を追加 | 追加によりポートフォリオ成績が改善するか（VR-052） |

> **順序5が重要である。** 凝った合議方式が単純な等ウェイトに勝てないことは珍しくない。
> 勝てなかった場合に**素直に等ウェイトを採用する**と先に決めておくことが、過剰最適化への最大の防御になる。
