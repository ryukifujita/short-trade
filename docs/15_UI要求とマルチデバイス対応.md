# 15. UI要求・マルチデバイス対応・半自動発注フロー

## 15.1 確定事項の追加

| ID | 項目 | 決定内容 |
|---|---|---|
| D-06 | 発注経路 | **A案: SBI証券の口座のまま、シグナル提示型の半自動運用**（`docs/13` §13.5） |
| D-07 | 主利用デバイス | **スマートフォンが主。PCは副**。ただし **PC / SP 両対応**を必須とする |

**D-06 により、FR-191（手動承認モード）は「代替経路」ではなく本システムの主経路になる。**
本ツールの責務は「シグナル生成・リスク判定・約定記録・損益追跡」であり、**発注操作そのものは利用者が SBI証券のアプリで行う**。

> **重要**: SBI証券では、**S株（単元未満株）の注文はスマートフォンでは「SBI証券 株」アプリからのみ可能**で、
> スマートフォンサイトからは注文できない。したがって利用者の発注動線は「本ツール（確認）→ SBI証券 株アプリ（発注）」となる。
> 出典: [SBI証券FAQ スマートフォンで単元未満株（S株）の注文はできますか？](https://faq.sbisec.co.jp/answer/5ecf7f9ed31ea500111ecc94?search=true)

## 15.2 S株の執行タイミングと、通知の設計

### 前提となる取引ルール（要一次情報確認）

S株の約定は1日3回（前場始値・後場始値・後場終値）で、注文を出した時間帯によって執行タイミングが決まる。

| 注文時間帯 | 執行タイミング |
|---|---|
| 13:30頃〜翌7:00頃 | 当日 **前場始値（9:00頃）** |
| 7:00頃〜10:30頃 | 当日 **後場始値（12:30頃）** |
| 10:30頃〜13:30頃 | 当日 **後場終値（15:30頃）** |

> **注意**: 公開情報のあいだで締切時刻の記載に揺れがある（13:30 とするものと 14:00 とするもの、
> 後場終値を 15:00 とするものと 15:30 とするもの）。2024年11月の東証取引時間延長の前後で情報が混在している可能性が高い。
> また SBI証券自身が「締め時間直後の注文は、直前の受付時間内の注文として約定することがある」と案内している。
> 出典: [SBI証券 単元未満株（S株）取引ルール](https://search.sbisec.co.jp/v2/popwin/attention/trading/stock_07.html) /
> [単元未満株（S株）の約定タイミング拡充のお知らせ](https://prtimes.jp/main/html/rd/p/000000373.000007957.html)

| ID | 要求 | 優先度 |
|---|---|---|
| CR-070 | 締切時刻・執行タイミングを **SBI証券の一次情報で確認**し、設定値として外出しすること（ハードコード禁止） | Must |
| CR-071 | 締切ぎりぎりの発注は意図しない執行タイミングになりうるため、**通知は締切の 60 分前**を既定とし、締切 15 分前を「最終期限」として扱うこと | Must |
| CR-072 | 東証の取引時間・SBI証券のルール変更に追随できるよう、締切と執行時刻を設定ファイルで変更可能とすること | Must |

### 通知スケジュール（既定案）

| 時刻 | 通知内容 | 対象執行 |
|---|---|---|
| 前日 20:00 | 翌営業日の推奨アクション（確定版） | 翌 9:00 |
| 当日 06:00 | 前日通知の再送＋夜間の変化（S安/上方修正等）による差分 | 当日 9:00 |
| 当日 06:30 | **最終リマインド**（未発注のシグナルがある場合のみ） | 当日 9:00 |
| 当日 09:30 | 前場の状況を反映した推奨アクション | 当日 12:30 |
| 当日 12:30 | 後場引け向けの推奨アクション | 当日 15:30 |
| 当日 13:15 | **最終リマインド**（未発注のシグナルがある場合のみ） | 当日 15:30 |
| 当日 16:00 | 約定確認のお願い＋当日サマリ | — |

| ID | 要求 | 優先度 |
|---|---|---|
| FR-301 | 上記の通知スケジュールを設定変更でき、通知を出す執行タイミングを選択できること（例: 「9時執行のみ使う」） | Must |
| FR-302 | シグナルが0件の場合は通知を送らない（またはサマリのみ）こと。通知疲れを避ける | Must |
| FR-303 | **損切りシグナルは通知の優先度を最上位**とし、他のシグナルと視覚的に区別すること | Must |
| FR-304 | 未発注のシグナルが締切を過ぎた場合、自動的に「見送り」として記録し、翌サイクルで再評価すること | Must |

## 15.3 半自動運用の業務フロー

```
[サーバ側・自動]                        [利用者・スマホ]
  日次バッチ / 場中判定
        │
        ├─ シグナル生成（戦略群 → 合議 → リスクゲート）
        │
        ├─ 発注指示カードを生成 ──────> ① プッシュ通知を受信
        │                                       │
        │                                ② カード一覧を開く
        │                                   （銘柄・数量・金額・根拠・期限）
        │                                       │
        │                                ③ [コードをコピー] をタップ
        │                                       │
        │                                ④ SBI証券 株アプリで発注
        │                                       │
        │  <──────────────────────────── ⑤ [発注済み] をタップ
        │        （想定価格・数量・執行枠を仮記録）
        │
        ├─ 執行時刻の経過を検知
        │
        ├─ 約定確認を通知 ─────────────> ⑥ 約定価格を入力（または未約定を選択）
        │                                    ※ 後日CSV取込で自動補正されるため概算可
        │
        ├─ ポジション・損益を更新
        │
        └─ 日次: 取引履歴CSVを取込 → 突合・補正（PL-040）
```

| ID | 要求 | 優先度 |
|---|---|---|
| FR-311 | 発注指示カードに、銘柄名・銘柄コード・売買区分・数量・想定約定金額・執行枠（9:00/12:30/15:30）・発注期限・根拠サマリ・損切り価格を表示すること | Must |
| FR-312 | 銘柄コード（および必要な入力値）をワンタップでクリップボードにコピーできること | Must |
| FR-313 | SBI証券アプリへの遷移手段（ディープリンクが利用可能な場合はリンク、不可の場合は手順の明示）を提供すること。**ディープリンクの可否は要確認であり、不可を既定として設計すること** | Must |
| FR-314 | 「発注済み」「見送り」をワンタップで記録でき、取り消し（誤タップ）も可能であること | Must |
| FR-315 | 約定価格の入力を省略した場合、執行タイミングの参考価格（始値／終値）で暫定計上し、**暫定値であることを明示**すること | Must |
| FR-316 | 取引履歴CSV（SBI証券からダウンロード）を取り込み、暫定値を実約定値へ**自動補正**できること。補正内容は差分として記録すること | Must |
| FR-317 | CSV取込は重複取込に耐える（冪等）こと | Must |
| FR-318 | 利用者が発注しなかった（見送り／期限切れ）シグナルの仮想成績を追跡し、**実行率と機会損失**を計測できること | Must |
| FR-319 | 発注操作の所要時間を短縮するため、1画面あたりのタップ数を「通知→発注済み記録」まで **3タップ以内**とすること | Should |

### 半自動特有のKPI（`docs/12` へ追加）

| KPI | 定義 | 目標 |
|---|---|---|
| シグナル実行率 | 発注済み件数 ÷ 発注指示件数 | ≥ 90% |
| 執行遅延 | シグナル生成から「発注済み」記録までの中央値 | ≤ 30分 |
| 機会損失 | 見送りシグナルの仮想損益の合計（プラスなら損失） | 月次で純損益の 20% 以内 |
| 約定価格の補正誤差 | 暫定計上価格と実約定価格の乖離 | 中央値 ≤ 0.5% |

> **設計上の含意**: 半自動では「人が実行しないこと」が最大のリスクになる。
> 実行率が下がるとバックテストの前提が崩れるため、実行率は成績と同格のKPIとして扱う。

## 15.6 セキュリティ・アクセス要求（モバイル前提の追加）

| ID | 要求 | 優先度 |
|---|---|---|
| NFR-070 | 本ツールは **SBI証券のログイン情報を一切保持しない**（発注は利用者がSBI証券アプリで行うため）。この設計を明示し、逸脱しないこと | Must |
| NFR-071 | 本ツールへのログインは、スマートフォンでの利用頻度を考慮し、生体認証（WebAuthn / パスキー）に対応すること | Should |
| NFR-072 | セッションはデバイス単位で管理し、紛失時に個別失効できること | Should |
| NFR-073 | 公共Wi-Fi等での利用を想定し、通信はすべて TLS、機微データはローカルストレージに平文で保持しないこと | Must |

> **NFR-070 は A案の大きな利点である。** 証券口座の認証情報を自作システムに預けないため、
> 情報漏洩時の被害が「シグナルと損益履歴の漏洩」に限定され、資産の直接的な毀損リスクがない。

## 15.9 根拠の可視化 — 注釈付きチャートと初心者向け解説

半自動運用では、利用者が「なぜこの売買なのか」を理解できないと実行率（FR-318）が落ちる。
根拠は**文章より先に絵で示し**、そのあと専門用語を使わない言葉で説明する。

### チャート画像の生成

| ID | 要求 | 優先度 |
|---|---|---|
| FR-341 | 全シグナルに対し、**判断根拠を書き込んだチャート画像を自動生成**し、発注指示カードから参照できること | Must |
| FR-342 | 書き込む注釈の種類を定義し、少なくとも次を描画できること：①トレンドの範囲 ②パターン（収縮・レンジ・ベース等）③エントリー条件となる価格線 ④ブレイク／シグナル発生点 ⑤出来高の特徴 ⑥エントリー価格 ⑦損切り価格 ⑧リスク幅（エントリーと損切りの間の帯） | Must |
| FR-343 | 注釈には**通し番号**を振り、解説文と 1 対 1 で対応させること。図のどこの話をしているかが常に特定できること | Must |
| FR-344 | 注釈テンプレートを**戦略ごとに持つ**こと（順張り：収縮とブレイク位置／逆張り：移動平均乖離と反発目標／イベント：発表時刻とギャップ） | Must |
| FR-347 | 生成したチャートと解説を**約定後も保存**し、後から振り返れること（トレード日誌としての利用） | Must |
| FR-349 | チャートは **SVG** で生成し、拡大しても劣化せず、ダークモードでも配色が破綻しないこと | Must |
| FR-350 | 描画はサーバ側で完結させ、**外部の画像生成API・有料サービスを使わない**こと（月額固定費0円の制約） | Must |

### 解説文

| ID | 要求 | 優先度 |
|---|---|---|
| FR-345 | 解説は**専門用語を使わずに書く**こと。やむを得ず使う語には用語チップを添え、タップで同一の説明を表示すること（用語集をデータとして保持） | Must |
| FR-346 | 解説文は戦略ごとのテンプレートに、当該シグナルの実測値を差し込んで生成すること。毎回同じ構造で読めること | Must |
| FR-348 | 「なぜ買うか」と**同じ大きさで「何がどうなったら間違いか」を必ず示す**こと。最低限、①損切り価格 ②時間による撤退条件 ③トレンド崩れの判定条件 を含めること | Must |
| FR-351 | 断定表現を使わないこと。「上がります」ではなく「上がりやすいと過去データでは出ています」と書く。将来の収益を約束する表現を出力しないこと（CR-004） | Must |
| FR-352 | 戦略の説明には**勝率・平均利益R・平均損失R・最大連敗**を必ず併記すること。「負ける回数のほうが多い」戦略であることを事前に知らせ、正常な連敗での運用停止を防ぐ | Must |

### 表示のUI

| ID | 要求 | 優先度 |
|---|---|---|
| UI-040 | 根拠画面を開いた最初の視野に、**チャートの縮小版**が入ること（文章が先に来ないこと） | Must |
| UI-041 | スマートフォンでは「縮小版 → タップで全画面」の2段階とすること。全画面では横スクロールでチャート全体を追えること | Must |
| UI-042 | 解説は先頭3件のみ表示し、残りは折りたたむこと。**解説を読まなくても発注操作は完了できる**こと | Must |
| UI-043 | 合議スコアの内訳・リスクゲートの記録など専門的な情報は解説の下に置き、初心者の導線を塞がないこと | Should |

### 解説文の構成（テンプレート例：ST-04 SEPA / VCP）

| # | 見出しの型 | 差し込む実測値 |
|---|---|---|
| 1 | 大きな流れの確認 | 200日線との位置関係、上昇期間 |
| 2〜4 | パターンの成立 | 各収縮の下げ幅と出来高の変化 |
| 5 | エントリー条件の宣言 | ピボット価格と、その根拠（直近高値） |
| 6 | 条件の成立 | 成立日と終値 |
| 7 | 出来高の裏づけ | 20日平均に対する倍率 |
| 8 | 執行の方法 | 執行枠、注文方法、想定価格 |
| 9 | 損切り | 損切り価格、リスク額、資金に対する比率 |
| ! | S株固有の注意 | 逆指値が置けないこと、想定損失を2倍で見積もること |
| ? | 撤退条件 | 価格・日数・トレンド崩れの3条件 |

## 15.7 影響を受ける既存要求の改訂

| 既存ID | 改訂内容 |

| FR-191 | Must（主経路）。「手動承認モード」ではなく「**半自動発注モード**」と呼称を変更 |
| FR-181〜FR-190（執行） | **Phase 4 までは対象外（Won't）**。発注は利用者が行うため。将来 B案／C案へ移行する際に復活させる |
| FR-201〜FR-205（ポジション管理） | 約定通知APIがないため、**「発注済み記録」＋「約定価格入力」＋「CSV取込」**を入力源とする |
| PL-040（突合） | 自動APIではなく**CSV取込による日次突合**として実装する |
| PL-042（約定ベース計算） | 維持。ただし CSV 取込前は暫定値である旨を明示（FR-315） |
| RM-001a〜e（論理ストップ） | 維持。**執行は利用者に依存するため、損切りシグナルの実行率を個別に監視すること**（FR-303 / FR-318） |
| RM-024（キルスイッチ） | 「全戦略停止＋全建玉クローズ」のうち、**クローズは指示の生成まで**。実行は利用者が行う |
| NFR-001〜002（レイテンシ） | Phase 4 までは非適用。日次・場中3回の判定であるため |
| NFR-010（稼働率） | 「立会時間中99.9%」ではなく「**通知スケジュールの各時刻に確実に処理が走ること**」に読み替える |

## 15.8 将来の完全自動化への移行性

A案は暫定解であり、資金・実績が積み上がった段階で B案（SBIネオトレード証券）／C案（三菱UFJ eスマート証券）への移行を検討する。

| ID | 要求 | 優先度 |
|---|---|---|
| NFR-080 | 「シグナル生成〜リスクゲート」と「執行」を明確に分離し、執行部分を**ブローカーアダプタの差し替え**で自動化へ移行できる構成とすること | Must |
| NFR-081 | 半自動モードにおける「発注指示」は、自動モードにおける「発注命令」と**同一のデータ構造**とすること | Must |
| NFR-082 | 移行時に過去の損益・成績データが連続して扱えること（口座が変わっても資金曲線が分断されないこと） | Should |
