# 08. 検証（バックテスト／フォワードテスト）要求（VR）

本章は BR-005 に対応する。**「バックテストで勝てた」は実運用の根拠にならない**という前提に立ち、
過剰最適化と情報漏洩を構造的に排除することを要求する。

## 8.1 バックテスト基盤

| ID | 要求 | 優先度 |
|---|---|---|
| VR-001 | バックテストと実運用で、特徴量計算・シグナル生成・意思決定のコードを共有すること | Must |
| VR-002 | イベント駆動型（時刻順にデータを流す）でシミュレートし、未来のバーを参照できない構造とすること | Must |
| VR-003 | 分足・ティックレベルでの再生に対応すること（デイトレ戦略の検証に必要） | Must |
| VR-004 | 上場廃止・市場変更銘柄を含む「当時のユニバース」を再現し、生存者バイアスを排除すること | Must |
| VR-005 | 決算・開示・ニュースは、**当時の公表時刻**を用いて配信すること（後日訂正値の混入禁止） | Must |
| VR-006 | 検証結果は乱数シード・データバージョン・コードバージョンとともに保存し、再現できること | Must |

## 8.2 コストと約定のモデル化

| ID | 要求 | 優先度 |
|---|---|---|
| VR-010 | 手数料（約定代金別）、信用金利、貸株料、逆日歩、消費税をコストとして計上すること | Must |
| VR-011 | スリッページを、注文サイズ／板厚／ボラティリティに依存するモデルで見積もること | Must |
| VR-012 | 指値の約定判定は、同値では約定しない等の保守的ルールを既定とすること | Must |
| VR-013 | 成行注文は次のティック／次の足の始値以降で約定させ、当該バーの安値・高値での都合の良い約定を禁止すること | Must |
| VR-014 | 流動性制約（1日の出来高に対する自己の売買比率上限）を適用すること | Must |
| VR-015 | ストップ高・安、売買停止、比例配分を再現し、約定できない状況を再現すること | Should |
| VR-016 | 楽観的仮定（best case）と保守的仮定（worst case）の両方で結果を出せること | Should |

## 8.3 過剰最適化の抑制

| ID | 要求 | 優先度 |
|---|---|---|
| VR-020 | 学習期間（In-Sample）と検証期間（Out-of-Sample）を分離し、OOS の結果のみを採否判断に用いること | Must |
| VR-021 | ウォークフォワード分析（ローリング学習→次期間検証）を標準手順とすること | Must |
| VR-022 | パラメータ感度分析を行い、最適点が孤立したピークでなく**安定した高原（プラトー）**にあることを確認すること | Must |
| VR-023 | 試行回数を記録し、多重検定バイアスを考慮した評価（例: デフレーテッド・シャープレシオ、PBO）を提示すること | Should |
| VR-024 | ランダム化検証（シャッフル、ブートストラップ、モンテカルロによる取引順序入替）で、成績が偶然でないことを確認すること | Should |
| VR-025 | パラメータ数と自由度を記録し、戦略の複雑度に上限を設けること | Should |

## 8.4 昇格ゲート（UC-04）

戦略・パラメータは以下のゲートを順に通過した場合のみ実運用ウェイトを与える。**基準値は運用開始前に確定させ、事後に緩めない。**

| ゲート | 内容 | 合格基準（既定案・調整可） |
|---|---|---|
| G1: バックテスト | OOS 期間での成績 | 取引数 ≥ 100、プロフィットファクタ ≥ 1.3、期待値 > 0、最大DD ≤ 15%、パラメータ感度がプラトー |
| G2: ロバストネス | 感度分析・モンテカルロ | パラメータ ±20% 変動でも PF ≥ 1.1、取引順序入替の 5 パーセンタイル DD ≤ 25% |
| G3: ペーパートレード | 実データでの模擬売買 | 最低 1 か月かつ 30 取引以上、期待値がバックテストの ±50% 以内、システム的な不整合ゼロ |
| G4: 少額実弾 | 最小サイズでの実売買 | 最低 1 か月、実現スリッページが想定の 2 倍以内、リスク上限違反ゼロ |
| G5: 本番ウェイト | 段階的なサイズ引上げ | 各段階で G4 の基準を維持。逸脱時は前段階へ差し戻し |

| ID | 要求 | 優先度 |
|---|---|---|
| VR-030 | 各ゲートの合否と根拠データを記録し、戦略のライフサイクルとして追跡できること | Must |
| VR-031 | ゲート基準を満たさない戦略に実弾ウェイトを割り当てられないこと（システム的に強制） | Must |
| VR-032 | 稼働中戦略の成績を継続監視し、基準割れ時は自動的に前段階へ差し戻すこと | Should |

## 8.5 ポートフォリオ（複合）レベルの検証

| ID | 要求 | 優先度 |
|---|---|---|
| VR-040 | 個別戦略だけでなく、アンサンブル後のポートフォリオとして検証できること | Must |
| VR-041 | 戦略間の相関行列、同時ドローダウン、寄与度分解を出力すること | Must |
| VR-042 | 合議のパラメータ（閾値、ウェイト方式）自体も VR-020〜VR-022 の対象とすること | Must |
| VR-043 | 「最良単一戦略」と「アンサンブル」を同一条件で比較し、BR-004 の達成を判定できること | Must |
| VR-044 | ストレスシナリオ（急落、ギャップ、流動性枯渇、連続ストップ安、システム障害）での想定損失を評価できること | Should |
