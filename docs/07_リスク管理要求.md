# 07. リスク管理・セーフティ要求（RM）

本章は BR-006 に対応する。**リスク管理要求は戦略のいかなる判断よりも優先される**。
リスクゲートは意思決定エンジンの下流に位置し、戦略・エンジンから無効化できない構造とする。

## 7.1 トレード単位のリスク

| ID | 要求 | 優先度 |
|---|---|---|
| RM-001 | 損切り価格のないポジションを保有しないこと。エントリー約定後、規定時間内に逆指値がブローカー側に置かれない場合、当該ポジションを成行でクローズすること | Must |
| RM-002 | 1トレードあたりのリスク額は口座資産の設定比率（既定: 0.5〜1.0%）を超えないこと | Must |
| RM-003 | 想定リスクリワードが下限（既定: 1.5）を下回るシグナルは採用しないこと | Should |
| RM-004 | 保有時間の上限（戦略ごと）を設け、超過時は自動手仕舞いすること | Should |
| RM-005 | ナンピン（含み損中の買い増し）は既定で禁止。許可する場合も総リスクが RM-002 の枠を超えないこと | Must |

## 7.2 ポートフォリオ単位のリスク

| ID | 要求 | 優先度 |
|---|---|---|
| RM-010 | 同時保有ポジションの想定リスク合計（ポートフォリオ・ヒート）に上限（既定: 口座の 3〜6%）を設けること | Must |
| RM-011 | 1銘柄あたりの最大投下金額・最大数量に上限を設けること | Must |
| RM-012 | 同一セクター／同一テーマへの集中に上限を設けること | Should |
| RM-013 | 同時保有ポジション数の上限を設けること | Must |
| RM-014 | レバレッジ（信用建玉総額 ÷ 口座資産）の上限を設けること | Must |
| RM-015 | 相関の高い銘柄群を1つのリスク単位として合算評価すること | Should |
| RM-016 | 対象銘柄の流動性（直近平均売買代金）に対する自己の建玉・注文比率に上限を設けること | Must |

## 7.3 損失上限とサーキットブレーカー

| ID | 要求 | 優先度 |
|---|---|---|
| RM-020 | 当日の純損失が設定額／設定比率に達した場合、当日の新規建てを全停止すること（デイリー・ロスリミット） | Must |
| RM-021 | 週次・月次の損失上限に達した場合、当該期間の新規建てを停止し、通知すること | Must |
| RM-022 | ドローダウンが段階閾値を超えた場合、ポジションサイズを段階的に縮小すること（例: -5%で50%、-10%で25%） | Must |
| RM-023 | 連敗回数が閾値を超えた戦略を自動停止すること | Should |
| RM-024 | 全戦略停止＋全建玉クローズを行う「キルスイッチ」を、UIとAPIの双方から実行できること | Must |
| RM-025 | 停止状態からの再開は人間による明示的操作を必要とし、自動再開しないこと | Must |

## 7.4 システム・運用リスク

| ID | 要求 | 優先度 |
|---|---|---|
| RM-030 | 市場データ接続断を検知した場合、新規建てを直ちに停止すること | Must |
| RM-031 | 発注API接続断・認証失効を検知した場合、通知し、復旧まで新規建てを停止すること | Must |
| RM-032 | 復旧時はブローカー側の建玉・注文を正として再同期し、同期完了まで発注しないこと | Must |
| RM-033 | 二重起動を防止し、同一口座に対する重複稼働を検知したら安全側で停止すること | Must |
| RM-034 | 想定外の例外発生時は「発注しない」を既定動作（fail-safe / fail-closed）とすること | Must |
| RM-035 | 単位時間あたりの発注件数・約定件数が想定を大きく超えた場合、自動的に発注を抑止すること（暴走検知） | Must |
| RM-036 | 想定と異なる建玉（未知の建玉、数量不一致）を検知した場合、通知し新規建てを停止すること | Must |
| RM-037 | 時刻同期（NTP）を行い、タイムスタンプのずれが閾値を超えたら警告すること | Should |

## 7.5 市場イベント・特殊状況

| ID | 要求 | 優先度 |
|---|---|---|
| RM-040 | ストップ高／ストップ安、売買停止、特別気配時は、当該銘柄への新規発注を抑止すること | Must |
| RM-041 | 値幅制限拡大、呼値の変更、制度信用規制（増担保・日々公表）等を検知し、対象銘柄のサイズを制限すること | Should |
| RM-042 | 決算発表・重要イベントを跨ぐ保有を、戦略ごとに許可／禁止設定できること | Must |
| RM-043 | 寄付直後・引け直前の高ボラ時間帯における発注を、戦略ごとに制限できること | Should |
| RM-044 | 空売り規制（価格規制、貸株在庫切れ）に抵触する注文を出さないこと | Must |
| RM-045 | 指数先物のサーキットブレーカー等、市場全体の異常時は自動売買を一時停止すること | Should |

## 7.6 取引行為に関する制約

| ID | 要求 | 優先度 |
|---|---|---|
| RM-050 | 約定させる意思のない注文の発注・即時取消の反復（いわゆる見せ玉に該当しうる行為）を行わない設計とすること | Must |
| RM-051 | 自己の売り注文と自己の買い注文を対当させる可能性のある発注を抑止すること | Must |
| RM-052 | 終値関与を目的とするような、引け間際の意図的な価格形成に関与しないこと | Must |
| RM-053 | 証券会社が定める API 利用条件（自動売買の可否、レートリミット、禁止行為）に適合すること | Must |
| RM-054 | 上記に抵触しうる発注パターンを検知するモニタを備え、検知時は発注を抑止して記録すること | Should |

## 7.7 リスク設定の管理

| ID | 要求 | 優先度 |
|---|---|---|
| RM-060 | リスク上限値は設定ファイルで一元管理し、変更履歴を残すこと | Must |
| RM-061 | 上限の緩和にあたっては確認ステップと理由記録を必須とすること | Must |
| RM-062 | 起動時にリスク設定の妥当性検査（未設定・非常識値の検出）を行い、不備があれば起動しないこと | Must |
| RM-063 | リスクゲートの各判定を、通過・却下の別と理由コード付きで記録すること | Must |
| RM-064 | リスクゲートの発動（各上限）に対する動作確認テストを、定期的に実施できること | Should |
