## 28.1 決算跨ぎ禁止は、トレンド戦略の優位性の半分以上を削る

決算跨ぎ禁止が効いた第3回と、効いていなかった第2回（`docs/27`）を、同じ設定（5万円・リスク 1%・滑り 0.1%）で並べる。

| 戦略 | | 第2回（禁止なし） | 第3回（禁止あり） |
|---|---|---|---|
| ST-06 | PF / 平均R / 総損益 | 1.51 / +0.20 / +13,360円 | **1.17 / +0.04 / +3,047円** |
| | 平均保有日数 | 19.8 | 15.6 |
| ST-09 | PF / 平均R / 総損益 | 2.44 / +0.81 / +15,513円 | **1.67 / +0.24 / +5,744円** |
| | 平均保有日数 | 43.7 | 18.6 |
| ST-12 | PF | 1.03 | 1.02（保有 3.4 日なので影響なし） |

資金制約を外した測定（相関用、リスク 0.25%）でも同じで、ST-06 の平均R は +0.20 → +0.09、
ST-09 は +0.29 → +0.03 に落ちた。

原因は明確である。現在の RM-001d は「決算前に **必ず** 手仕舞う」で、ST-06 は 386 回、ST-09 は 44 回の
エントリーを見送り、さらに保有中の玉を決算前に切っている。**トレンドフォローの利益の相当部分は決算をまたいだ
ときの窓（ギャップ）から来る**。それを全部捨てれば、平均保有日数が縮み、大きい勝ちだけが消える。
この規則は `docs/14` で「S株はザラ場で損切りできない → 決算のギャップは致命的」という理由で確定した前提だが、
**その安全のために払う代償が、これほど大きいとは見積もっていなかった。** 数字で見て決め直す必要がある。

### 3つの方針を次回の比較に載せた

| 方針 | 内容 | 期待される位置 |
|---|---|---|
| `exit`（現行） | 前後1営業日はエントリー禁止。保有中の玉は決算前に必ず手仕舞う | 最も安全、最も収益が低い |
| `entry_only` | エントリー禁止だけ。保有中の玉は決算をまたいで持つ | 収益は第2回に近い。ギャップ損は損切り幅×2（RM-001b）を超えうる |
| `cushion` | 含み益が **+1R 以上**なら持ち越す。未満なら手仕舞う | 中間。「余裕のある玉だけギャップに晒す」 |

`compare` は現行方針の格子（リスク×滑り）に加え、**滑り 0.1% の行についてだけ** `entry_only` と `cushion` を
追加で走らせる。次回の `run_mac.command` で3方針の PF・最大DD・最悪トレードが並ぶ。

**これは利用者の判断である**（RM-001d は確定した前提の変更にあたる）。私の推奨は `cushion`（+1R）で、
理由は「ギャップで失うのは含み益であって元本ではない」状態に限って跨ぐからである。ただし数字を見てから決める。

| ID | 要求（新規） |
|---|---|
| RM-072 | 決算跨ぎ方針は `exit` / `entry_only` / `cushion` の3つを同一データで比較し、**最大DDと最悪トレードの悪化幅**を見て決める。`cushion` を採る場合、閾値 R は探索しない（+1R 固定） |

## 28.2 F4（短期平均回帰）は 5万円運用では見送り — DEC-069

ST-16（移動平均乖離率）の結果。

| ST-16 | リスク | 滑り | 取引数 | 勝率 | PF | 平均R | 最大DD |
|---|---|---|---|---|---|---|---|
| | 1% | 0% | 34 | 55.9% | 1.44 | +0.12 | −1.9% |
| | 1% | 0.1% | 34 | 55.9% | **1.30** | +0.09 | −2.0% |
| | 2% | 0% | 39 | 61.5% | 1.24 | +0.08 | −5.8% |
| | 2% | 0.1% | 39 | 59.0% | **1.10** | +0.04 | −6.4% |
| 資金制約なし（0.25%、滑り 0） | | | 97 | 56.7% | 1.19 | +0.06 | — |

10年で 34〜97 取引しかなく、平均R は +0.06〜+0.12。滑り 0.1% で PF 1.30（34 取引）と 1.10。
資金制約なしでも滑り 0 で 1.19 なので、0.1% を載せれば 1.1 を割る。ST-12（PF 1.02 / 0.88）よりましだが、
**コストに対する余裕がなく、標本も少ない。** DEC-068 の後段の基準（0.1% で PF 1.2 未満なら見送り）に照らし、
F4 は見送る。

| ID | 決定 | 内容 |
|---|---|---|
| DEC-069 | **F4（短期平均回帰）は Phase 2 の稼働候補から外す。** ST-12・ST-16 とも測定は続ける（`compare` に残す）が、稼働の組合せには入れない | 5万円・S株・日足の制約では、1トレードの値幅が往復コストに耐えない。資産が増えて指値が使える環境（単元株）になったら再検討 |

相関の面では ST-12 × ST-16 の残差相関は **0.22**（予想 0.70）で、F4 内の分離は成立していた
（`docs/18` §18.4 課題2）。分離はできたが、どちらも稼働に足りなかった、というのが結論である。

## 28.3 稼働候補は F1（ST-06）と F3（ST-09）の2本に絞られた

| 因子 | 代表 | 状態 |
|---|---|---|
| F1 トレンド | ST-06 | 稼働候補。決算方針で成績が倍半分変わる |
| F2 ボラ収縮 | ST-04 | 標本不足（下記） |
| F3 相対強度 | ST-09 | 稼働候補 |
| F4 平均回帰 | ST-12 / ST-16 | **見送り（DEC-068 / 069）** |
| F5 イベント | ST-23 | 未実装 |

ST-06 × ST-09 の残差相関は **0.49**（予想 0.35、前回 0.41）。0.7 未満なので統合はしないが、
2本ともトレンドを買う戦略で、**分散効果は限定的**である。「複合的に組み合わせる」という当初の目的に対して、
現時点で組み合わせられるのは実質 F1 と F3 だけだと正直に書いておく。
F2（ST-04）が動くかどうかが、Phase 2 の残りの焦点になる。

## 28.4 ST-04 のファネル — 候補を殺しているのは3条件

30銘柄 × 延べ 73,260 日から、どの条件で候補が減るか（「ここまで AND」の残り）。

| 条件 | ここまで AND | 残存率 |
|---|---|---|
| トレンドテンプレート 8 条件 | 18,568 | 25% |
| 相対強度 PCTRANK ≥ 70 | 12,911 | 18% |
| 収縮 3 回以上 | 12,911 | 変化なし |
| **押し3 ≤ 押し1 × 0.5** | **1,404** | **1.9%** |
| 押し幅が段階的に縮小 | 1,017 | 1.4% |
| 出来高が段階的に減少 | 326 | 0.4% |
| 終値 > ピボット | 219 | 0.3% |
| **前日はピボット以下（クロス日のみ）** | **32** | **0.04%** |
| **ブレイク日の出来高 ≥ 20日平均 × 1.5** | **3** | **0.004%** |
| レジーム | 2 | |

- **押し3 ≤ 押し1 × 0.5** が 89% を落とす。Minervini の「収縮ごとに半分」は原法どおりだが、機械的な
  ジグザグ（ATR×1.5）で測った押し幅は、目視より大きくばらつく。
- **クロス日 → 出来高 1.5 倍** で 32 → 3。ピボットを上抜けた当日に出来高が 1.5 倍という要求は、
  大型株では稀である（大型株は出来高の変動が小さい）。
- ユニバースを 30 → 300 に広げれば単純計算で 20 件前後になる。**判定にはまだ足りないが、方向は見える。**

条件を緩めるのは最適化であり、OOS の前にやらない（`docs/18` §18.5、自由度 21 の枠）。
先にユニバースを広げる。

## 28.5 ユニバース拡張 — 1回だけ開くファイルを追加した
