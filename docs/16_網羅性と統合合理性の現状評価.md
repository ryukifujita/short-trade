# 16. 網羅性と、統合の合理性 — 現状評価

> 問い: **「短期売買の有名投資家の投資分析手法は、すべて網羅して売買ロジックに合理的かつ複合的に組み込まれているか？」**
>
> 答え: **いいえ。** 現時点では「棚卸しと設計」の段階であり、「組み込まれている」段階ではない。
> 本章は、何がどこまでできていて、何ができていないかを、ごまかさずに記録する。

## 16.1 「組み込まれている」の3条件

手法が売買ロジックに合理的かつ複合的に組み込まれている、と言うには次の3つが必要である。

| 条件 | 内容 | 現状 |
|---|---|---|
| ① **ルール化** | 手法が、検証可能な条件式（エントリー／エグジット／サイズ／適合レジーム）へ翻訳されている | **一部**。カタログには63件あるが、条件式まで書き下したものは 0 件。カタログは「要点の記述」であり実装仕様ではない |
| ② **統合設計** | 複数手法が、相場環境に応じて重み付けされ、競合が解決される設計になっている | **設計のみ**。DEC-020〜028 として文書化済みだが、重み・閾値・レジーム定義はすべて**根拠のない仮置き** |
| ③ **実証** | その統合が、単一手法より優れることがデータで確認されている | **ゼロ**。バックテストを1本も実施していない。BR-004（最大DD 20%低減）は**目標であって結果ではない** |

**したがって現状は「①が部分的、②が紙の上、③が未着手」である。**
「複合的に組み込まれた売買ロジック」と呼べるものは、まだ存在しない。

### まだ網羅していないもの

以下は意図的に、または未調査で含めていない。

| 領域 | 理由 |
|---|---|
| 高頻度取引・マーケットメイクの手法 | C-04（レイテンシ競争に参入しない）により対象外 |
| オプション戦略（Sheldon Natenberg 等） | 対象商品外（Won't） |
| 統計的裁定・ペアトレード | 空売りが必要なため現物のみのスコープでは不可 |
| 機械学習ベースの手法（López de Prado 等） | DEC-027 として設計に含むが、Phase 3 以降。データ量が足りない |
| 個人ブログ・SNS由来の手法 | 出典の信頼性を評価できないため、書籍・公開インタビューに情報源を限定している |
| 非公開の手法 | 原理的に不可能 |

> **「すべて網羅」は、原理的に達成できない目標である。** 手法は今も生まれ続けており、
> 有効な手法ほど公開されにくい。カタログの目的は完全性ではなく、**「主要な考え方の型を取りこぼさないこと」**である。

## 16.3 統合の合理性 — 現時点で認識している4つの問題

### 問題1: 見かけの分散（因子の重複）

カタログ上は別の手法でも、**実質的に同じことを見ている**ものが多い。

| 因子 | 実質的に同じ判断をしている手法 |
|---|---|
| **ベースからのブレイクを買う** | ST-01（ピボタルポイント）、ST-02（ボックス）、ST-03（CAN SLIM）、ST-04（VCP）、ST-05（出来高ブレイク）、ST-06（ドンチャン）、ST-07（エピソディックピボット）、ST-11（新高値）、ST-35（ステージ2）、ST-44（クラシカルパターン） |
| **ボラティリティ収縮のあとの拡大** | ST-04（VCP）、ST-38（NR7）、ST-39（ボラティリティブレイクアウト）、ST-47（ボリンジャースクイーズ） |
| **相対的な強さ** | ST-09（モメンタム）、ST-10（RSレーティング）、ST-03 の一部 |
| **短期の行き過ぎからの反発** | ST-12（RSI2）、ST-13（%b）、ST-16（移動平均乖離）、ST-17（小型株分散逆張り） |

10本の戦略を合議させても、全部が同じ因子なら**分散にはならない**。
不調期には10本が同時に沈む。「網羅した」という感覚が、かえってリスクを見えなくする。

| ID | 要求（新規） | 優先度 |
|---|---|---|
| VR-045 | 実装した戦略のシグナル系列間の相関を測定し、**相関 0.7 以上の戦略は同一因子として扱う**こと。合議の重みは因子単位で配分し、同一因子内での重複計上を禁止すること | Must |
| VR-046 | 戦略を因子（トレンド追随／収縮拡大／相対強度／平均回帰／イベント／需給）に分類し、**因子ごとの寄与と相関を定期的に報告**すること | Must |
| DEC-062 | 合議に組み込む戦略は、**直交性（低相関）が確認されたもの**に限ること。相関の高い戦略は代表1本を選び、残りは確認用フィルタとして使うこと | Must |

### 問題2: 重み・閾値に根拠がない

DEC-020 の統合スコア `戦略ウェイト × 確信度 × レジーム適合度` は、**形式は定義したが、値の決め方を定義していない**。
確信度 0.71 という数字が何を意味するのか、閾値 0.6 で切ることが妥当なのかは、現時点で誰も知らない。

| ID | 要求（新規） | 優先度 |
|---|---|---|
| DEC-063 | 確信度は「そのシグナル条件での過去の平均R」など、**実測にひもづく定義**とすること。戦略作者の主観スコアを直接使わないこと | Must |
| DEC-064 | 統合スコアの閾値は、**閾値を変えたときの成績曲線がなだらかであること**を確認したうえで決めること（孤立したピークを選ばない） | Must |
| DEC-065 | 合議方式そのもの（加重平均／多数決／メタラベリング）を比較検証し、**採用理由を記録**すること | Must |

### 問題3: レジーム別の重み付けに必要なサンプルが足りない

DEC-022c（直近成績による動的ウェイト）とレジーム別ウェイトは、**各レジームで十分な試行回数**があって初めて成立する。
しかし本プロジェクトの条件では：

| 制約 | 帰結 |
|---|---|
| 日足・1日1回判定 | 1戦略あたり年間のトレード数は数十件 |
| レジームが4象限×方向 | 1レジームあたりの試行数は年間 10件未満になりうる |
| 資金5万円・S株 | 同時保有できる銘柄数が限られ、試行がさらに減る |

**年間10件の実績で重みを動かすのは、統計ではなく偶然を追いかける行為になる。**

| ID | 要求（新規） | 優先度 |
|---|---|---|
| VR-047 | 動的ウェイト・レジーム別ウェイトを有効にする**最低試行回数**を定め、それを下回る間は基準ウェイトを維持すること（既定: 30件） | Must |
| VR-048 | 試行数を確保するため、パラメータ推定は**銘柄横断でプールした検証**（1銘柄ごとの最適化を禁止）で行うこと | Must |
| VR-049 | 実弾の試行数が不足する期間は、**ペーパートレードのシグナルも成績評価に含めて**サンプルを補うこと。実弾とペーパーは区別して記録すること | Should |

### 問題4: 手法を増やすほど過剰最適化しやすくなる

これが最も重要である。**網羅は、そのままでは品質を下げる。**

- 手法を63件用意し、それぞれにパラメータがあれば、試行の組合せは容易に数万通りになる。
- そのなかから「バックテストで最も成績が良かった組合せ」を選べば、**選んだ時点で必ず過剰最適化している**。
- 多重検定の問題であり、試行回数が増えるほど「偶然よく見えるだけの組合せ」が必ず現れる。

| ID | 要求（新規） | 優先度 |
|---|---|---|
| VR-050 | 検証で試した組合せ・パラメータの**総試行回数を記録**し、多重検定を考慮した指標（デフレーテッド・シャープレシオ、PBO）で評価すること（VR-023 の強制適用） | Must |
| VR-051 | 同時に稼働させる戦略数に**上限**を設けること（既定: 因子あたり2本、全体で8本まで）。上限を超えて追加する場合は、既存の1本を停止すること | Must |
| VR-052 | 新規戦略の採用は、**追加によってポートフォリオの成績が改善すること**を条件とすること。単体成績が良いだけでは採用しない | Must |

> **設計方針の転換**: 目標を「網羅的に実装する」から
> **「網羅的に棚卸ししたうえで、直交する少数を選んで実装する」**に改める。
> カタログ63件は**在庫**であり、実装リストではない。

## 16.4 BR-001 の改訂

| 旧 | 新 |
|---|---|
| BR-001: 著名投資家の短期売買手法を網羅的に調査し、検証可能なルールとして棚卸しする | BR-001: 著名投資家の短期売買手法を**網羅的に棚卸し**し、そのうち**因子として直交する少数を選抜**して実装する。棚卸しの網羅性と、実装の絞り込みを、別々の指標で管理する |
| 成功指標: カタログに20手法以上、うち12以上が実装可能判定 | 成功指標: **カタログ 60件以上**／**因子分類が全件に付与されている**／**同時稼働は8本以下で、因子あたり2本以下**／**稼働戦略間の平均相関 0.5 以下** |

## 16.5 現状のスコアカード

| 観点 | 状態 | 根拠 |
|---|---|---|
| 主要な手法の型を取りこぼしていないか | **概ね達成**（63件） | `docs/03` 全体。ただし「すべて」ではない（16.2） |
| 各手法が条件式まで書き下されているか | **未着手（0/63）** | カタログは要点の記述に留まる。Phase 1 の作業 |
| 統合設計が文書化されているか | **達成** | `docs/04` DEC-001〜065 |
| 統合の重み・閾値に根拠があるか | **なし** | 全て仮置き。DEC-063〜065 で対処予定 |
| 因子の重複を排除できているか | **未着手** | VR-045/046・DEC-062 で対処予定 |
| 統合が単一手法に勝つことを実証したか | **未着手** | バックテスト未実施。Phase 1〜3 の作業 |
| 過剰最適化への備えがあるか | **設計済・未適用** | VR-020〜025、VR-050〜052 |

**この表がすべて「達成」になるまでは、「複合的に組み込まれている」とは言わない。**

## 16.6 これを解消するための最短経路

| 順序 | 作業 | 対応するPhase |
|---|---|---|
| 1 | カタログ63件に**因子タグ**を付与し、因子ごとに代表手法を1〜2本選ぶ | Phase 0（残作業） |
| 2 | 選抜した手法を**条件式として書き下す**（エントリー／エグジット／サイズ／レジーム） | Phase 1 |
| 3 | 1本ずつ**単体でバックテスト**し、G1・G2 を通す | Phase 1〜2 |
| 4 | シグナル系列の**相関行列**を出し、直交性を確認（VR-045） | Phase 2 |
| 5 | 合議方式を**3方式比較**し、採用理由を記録（DEC-065） | Phase 3 |
| 6 | アンサンブル vs 最良単一戦略を**同一条件で比較**（VR-043）→ BR-004 の判定 | Phase 3 |

**現在地は「1」の手前である。**
