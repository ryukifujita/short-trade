# 05. 機能要求（FR）

## 5.1 マーケットデータ

| ID | 要求 | 優先度 |
|---|---|---|
| FR-101 | リアルタイム株価（現在値・出来高・気配）を購読し、購読銘柄の更新を欠落なく処理できること | Must |
| FR-102 | 板情報（最良気配および複数段の気配数量）を取得できること | Should |
| FR-103 | 歩み値（約定履歴）を取得し、約定サイズ・方向の集計ができること | Should |
| FR-104 | 分足・日足の時系列を生成・保存し、任意期間の再生（リプレイ）ができること | Must |
| FR-105 | 株式分割・併合・配当等のコーポレートアクションを反映した調整済み株価を保持すること | Must |
| FR-106 | 決算・適時開示・ニュースを時刻付きで取得し、銘柄に紐づけられること | Should |
| FR-107 | ファンダメンタルデータ（EPS・売上・成長率・コンセンサス）を取得できること | Should |
| FR-108 | データ欠損・異常値（ゼロ値、極端な飛び値、時刻逆転）を検知し、シグナル生成を抑止できること | Must |
| FR-109 | データ源を差し替え可能な抽象化レイヤ（アダプタ）で扱うこと | Must |

## 5.2 ユニバース・スクリーニング

| ID | 要求 | 優先度 |
|---|---|---|
| FR-121 | 売買対象ユニバースを、市場区分・時価総額・平均売買代金・株価水準・上場経過日数等で定義できること | Must |
| FR-122 | 整理銘柄・監理銘柄・貸借不適格・信用規制銘柄を自動除外できること | Must |
| FR-123 | ユニバースを日次で再構築し、変更差分を記録すること | Must |
| FR-124 | 戦略ごとに個別のサブユニバースを指定できること | Should |
| FR-125 | 手動の売買禁止リスト（ブラックリスト）を設定でき、必ず優先されること | Must |

## 5.3 特徴量・指標計算

| ID | 要求 | 優先度 |
|---|---|---|
| FR-141 | 移動平均、ATR、RSI、ADX、ボリンジャーバンド、VWAP、出来高倍率、乖離率、相対強度などの基本指標を提供すること | Must |
| FR-142 | パターン検出（レンジ／ボックス、フラッグ、カップウィズハンドル、ボラティリティ収縮）を提供すること | Should |
| FR-143 | 指標計算はバックテストと実運用で**同一の実装**を用いること（二重実装の禁止） | Must |
| FR-144 | 各指標が「確定足」のみを参照するか「未確定足」を含むかを明示指定できること（ルックアヘッド防止） | Must |

## 5.4 戦略実行

| ID | 要求 | 優先度 |
|---|---|---|
| FR-161 | 戦略モジュールをプラグインとして追加・削除でき、再デプロイなしで有効／無効を切替できること | Should |
| FR-162 | 戦略ごとにパラメータをファイル／UIで設定でき、変更履歴が残ること | Must |
| FR-163 | 戦略ごとに稼働モード（バックテスト／ペーパー／実弾）を個別に設定できること | Must |
| FR-164 | 戦略の実行時間帯（寄付のみ、場中、引けのみ等）を指定できること | Must |
| FR-165 | 1つの戦略の例外・遅延が他戦略や執行を停止させないこと（分離実行） | Must |

## 5.5 執行（オーダー管理）

> **改訂（2026-09-10）**: A案（半自動）の採用により、**FR-181〜FR-190 は Phase 4 までスコープ外（Won't）**。
> 発注は利用者が SBI証券 株アプリで行う。本ツールの責務は「発注指示カードの生成・通知・実行記録」であり、
> 要求は [`docs/15_UI要求とマルチデバイス対応.md`](15_UI要求とマルチデバイス対応.md) §15.3（FR-301〜FR-336）に定義する。
> 本節は将来 B案／C案で自動発注へ移行する際の要求として維持する。


| ID | 要求 | 優先度 |
|---|---|---|
| FR-181 | 成行・指値・逆指値・逆指値付通常・引け成行（クロージングオークション）を発注できること | Must |
| FR-182 | 現物買い／売り、信用買い／信用売り（空売り）、返済（決済）を発注できること | Must |
| FR-183 | 発注は冪等キーを持ち、リトライで二重発注が起きないこと | Must |
| FR-184 | エントリー約定後、**遅滞なく損切り注文（逆指値）をブローカー側に発注**すること | Must |
| FR-185 | 利確・損切りを OCO（どちらか約定で他方取消）として管理し、片側約定時に他方を確実に取り消すこと | Must |
| FR-186 | 未約定注文の訂正・取消ができ、一定時間で自動失効（GTD/IOC相当）を設定できること | Must |
| FR-187 | 発注レートリミット（秒間・分間の上限）を守り、超過時はキューイングまたは抑止すること | Must |
| FR-188 | 大口注文の分割執行（TWAP／VWAP／出来高比率）ができること | Could |
| FR-189 | 値幅制限（ストップ高／安）、売買停止、比例配分時の挙動を安全側に扱うこと | Must |
| FR-190 | 発注前に「余力・建玉上限・規制」を検査し、不足時は発注せず理由を記録すること | Must |
| FR-191 | **半自動発注モード**（シグナルを提示し、利用者が証券会社アプリで発注、結果を記録）を主経路として提供すること | **Must**（A案の主経路。詳細は docs/15） |

## 5.6 ポジション・約定管理

> **改訂**: 約定通知APIが使えないため、入力源は「発注済み記録 → 約定価格入力 → 取引履歴CSV取込」となる（`docs/15` §15.3）。


| ID | 要求 | 優先度 |
|---|---|---|
| FR-201 | 約定通知を受けてポジション（数量・平均取得単価・建日・戦略ID）を更新すること | Must |
| FR-202 | 建玉の帰属戦略を保持し、部分約定・部分決済でも戦略別に正しく按分できること | Must |
| FR-203 | ブローカー側の建玉・注文・余力と自システムの状態を定期的に突合し、乖離を検知・通知すること（A案では**取引履歴CSVの取込による日次突合**として実装） | Must |
| FR-204 | 起動時・再接続時にブローカー側の情報を正として状態を復元できること（A案では**最後に取り込んだCSVを正**とする） | Must |
| FR-205 | ~~信用建玉の期日・逆日歩・貸株料・金利を保持し、コストに反映すること~~ → **現物のみのため適用外（Won't）** | Won't |

## 5.7 監視・通知・操作

> **改訂**: 通知はスマートフォンへのプッシュが主経路となり、要求は `docs/15` §15.5（FR-331〜FR-336）へ拡張されている。


| ID | 要求 | 優先度 |
|---|---|---|
| FR-221 | ダッシュボードで、稼働状態・接続状態・当日損益・建玉一覧・注文一覧・直近シグナルを一画面で確認できること | Must |
| FR-222 | 重要イベント（発注・約定・損切り執行・上限抵触・接続断・戦略停止）をプッシュ通知できること | Must |
| FR-223 | 全停止（キルスイッチ）、戦略単位の停止、個別ポジションの即時クローズ**指示の生成**を、UIから1操作で実行できること。**A案では実際のクローズ発注は利用者が行う**（RM-024 の改訂） | Must |
| FR-224 | 通知チャネル（メール／モバイルプッシュ／チャット）を設定できること | Should |
| FR-225 | 全操作・全判断を追記専用の監査ログに残すこと | Must |
