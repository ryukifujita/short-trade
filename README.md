# short-trade — 複合戦略・自動売買意思決定ツール 要求定義

著名投資家の短期売買手法を体系的に学習・ルール化し、それらを**複合的に組み合わせた売買意思決定を自動化**し、
**リアルタイムで収益額（実現損益・含み損益）を可視化**するトレードツールの **要求定義（Requirements Definition）** です。

本リポジトリは **要求定義ドキュメント・手法カタログ（構造化データ）・検証基盤の実装** を管理します。

**はじめての方**: [docs/22 はじめかた](docs/22_はじめかた.md) を見てください。
`start_windows.bat`（Windows）または `start_mac.command`（Mac）を**ダブルクリックするだけ**で設定画面が開きます。

**コマンドで動かす場合**:

```bash
pip install -r requirements.txt
PYTHONPATH=src python -m short_trade setup       # ブラウザで認証情報を入力 → 接続確認〜基準線まで自動
PYTHONPATH=src python -m short_trade selfcheck   # 仕様ファイルの検査（ネットワーク不要）
python -m pytest tests/ -q                       # テスト 50件
```

実装の現況は [docs/20](docs/20_実装状況.md) を参照してください。実装は要求定義の合意後、`docs/10_ロードマップと段階スコープ.md` の
フェーズに沿って着手します。

## 要求IDの体系

| 接頭辞 | 意味 |
|---|---|
| `BR-xxx` | 事業要求（Business Requirement） |
| `FR-xxx` | 機能要求（Functional Requirement） |
| `DEC-xxx` | 意思決定エンジン要求 |
| `PL-xxx` | 損益可視化要求 |
| `RM-xxx` | リスク管理要求 |
| `VR-xxx` | 検証要求 |
| `NFR-xxx` | 非機能要求 |
| `DR-xxx` | データ要求 |
| `CR-xxx` | 制約・法規制要求 |
| `UI-xxx` | UI・マルチデバイス要求 |

優先度は **MoSCoW**（`Must` / `Should` / `Could` / `Won't(今回は対象外)`）で表記します。

## 確定した運用前提

| 項目 | 決定 |
|---|---|
| 運用資産規模 | 初期 **5万円** |
| 取引種別 | **国内株式 現物のみ**（信用取引は行わない） |
| 空売り | **スコープ外** |
| 自動化レベル | **半自動（A案）**。シグナル生成・リスク判定・損益追跡は自動、**発注操作のみ利用者がSBI証券アプリで実施**（docs/13 §13.5・docs/15） |
| 証券会社 | **SBI証券**（現物の個人向け発注APIが確認できないため、口座はそのままで半自動運用） |
| 取引単位 | **S株（単元未満株）** を既定。1日1回判定の日足スイング運用 |
| 主利用デバイス | **スマートフォンが主、PCが副**。単一のレスポンシブWeb（PWA）で両対応 |

詳細と、この前提が各要求へ与える影響は [docs/14](docs/14_確定した運用前提と影響分析.md) を参照。

## 重要な前提

- 本ツールは **利用者自身の資金による自己売買** を対象とします。第三者への助言・運用受託は対象外です（`docs/11_法規制と前提制約.md`）。
- 本ドキュメントに記載する投資家手法は、**書籍・公開インタビュー等で公表されている一般的な考え方**を、
  検証可能なルールへ翻訳する目的で整理したものです。原著者の手法そのものの再現を保証するものではありません。
- **収益は一切保証されません。** 自動売買は損失を自動的に拡大させうるため、リスク管理要求（RM-xxx）は Must として扱います。
- 資金5万円の段階は**収益獲得ではなく検証が目的**です。金額目標より「誤発注ゼロ・上限違反ゼロ・突合差異ゼロ」を優先します。
